# RPG-Silent 开发计划

## 当前方向

当前项目是一个第三人称 RPG 原型。下一步目标不是继续堆新系统，而是先把已经存在的移动、战斗、技能、UI、场景加载整合成一个稳定的最小可玩版本。

短期目标：

1. 从 `StartScene` 启动游戏。
2. 点击开始后加载 `Main` 场景。
3. 玩家可以正常移动、跳跃、翻滚、攻击。
4. 使用一套统一的战斗和连击系统。
5. 主界面 UI 显示真实玩家数据。
6. 完成一个小战斗闭环：进入场景、攻击敌人、受到伤害、击败敌人、显示结果。

## 下一步优先做什么

### 1. 先确认 Unity 能正常编译

打开 Unity，先处理 Console 里的编译错误。

重点检查：

- `PlayerAnimationController` 是否配置了有效的 `AnimationData`。
- `PlayerSkillController` 是否能找到普通攻击配置，找不到时是否能回退到普通攻击状态。
- `UIManager`、`SceneLoaderManager`、`InputManager` 是否存在于启动场景。
- Addressables 是否能加载 `UI/StartUI`、`UI/LoadingUI`、`UI/MainUI`、`Scenes/Main`。

完成标准：

- Unity Console 没有脚本编译错误。
- 点击 Play 后能打开开始界面。

### 2. 稳定游戏启动流程

确认启动路径：

- `StartScene` 作为启动场景。
- `GameStart` 打开 `StartUI`。
- `StartUI` 打开 `LoadingUI`。
- `LoadingUI` 加载 `Scenes/Main`。
- 主场景加载完成后打开 `MainUI`。

建议工作：

- 如有需要，在 Build Settings 里启用正确的启动场景。
- 确认需要跨场景存在的 Manager 使用了 `DontDestroyOnLoad`。
- 加载 `Main` 后确认每个 Manager 只有一个实例。

完成标准：

- Play Mode 下可以稳定从开始菜单进入主场景。

### 3. 完成唯一一套战斗和连击系统

项目现在应该只保留这条战斗路径：

- 输入入口：`PlayerSkillController`
- 连击配置：`SkillData.CanCombo`、`SkillData.NextComboSkill`、`SkillData.ComboInputWindow`
- 动画播放：`PlayerAnimationController`
- 命中检测：暂时保留在 `AttackState`，后续改成动画事件触发

建议工作：

- 创建普通攻击 `SkillData` 资源。
- 如果要做连击，继续创建第二段、第三段攻击的 `SkillData`。
- 创建或确认 `SkillDatabase` 资源，并设置 `NormalAttackSkill`。
- 普通攻击如果不消耗能量，把 `EnergyCost` 设为 `0`。
- 后续把 `AttackState.Enter` 里的即时命中检测移动到动画事件。

完成标准：

- 左键可以触发一次普通攻击。
- 在连击窗口内再次点击左键，可以触发下一段攻击。
- 没有其他脚本再处理左键连击逻辑。

### 4. 把玩家数据接到 UI

`MainUI` 目前还是示例数据，后续要接真实角色数据。

建议工作：

- 新增一个玩家属性组件，管理 HP、能量、金币、货币等数据。
- `MainUI.UpdateHP`、`UpdateMP`、`UpdateGold`、`UpdateMoney` 使用真实数据刷新。
- 玩家受伤、释放技能、获得奖励时主动刷新 UI。

完成标准：

- 玩家受伤后 HP 条变化。
- 释放技能后能量条变化。
- 获得奖励后金币或货币变化。

## 第一阶段：核心稳定

目标：先把已有原型跑稳，不急着加复杂系统。

任务：

- 整理 Manager 生命周期，避免重复单例。
- 确认 Addressables 分组和地址正确。
- 给场景必要引用补空值保护。
- 清理临时日志，统一中文或英文日志。
- 删除空脚本和无用脚本。
- 暂时可以继续使用旧输入 API，但长期不要和新版 Input System 混用。

交付结果：

- 游戏可以稳定从开始界面进入主场景，并完成一次基础玩家操作。

## 第二阶段：战斗与动画

目标：让玩家战斗逻辑稳定、可配置、手感可调。

任务：

- 只使用 `SkillData` 作为连击配置来源。
- 使用动画事件控制攻击判定时机。
- 增加攻击命中帧、收招时间、连击输入窗口。
- 明确技能是否可以被打断。
- 增加命中特效、打击反馈、伤害数字或屏幕震动。
- 敌人不要被一击直接销毁，改成 HP 归零后死亡。

交付结果：

- 完成一套基础战斗闭环：普通攻击、连击、敌人受伤、玩家受伤、死亡。

## 第三阶段：敌人与遭遇设计

目标：让敌人从测试对象变成真正的游戏单位。

任务：

- 增加敌人属性：HP、伤害、移动速度、攻击距离、攻击冷却。
- 增加敌人状态：待机、追击、攻击、受击、死亡。
- 敌人攻击也使用动画事件控制伤害时机。
- 增加简单出生点或触发区域。
- 敌人死亡后掉落奖励。

交付结果：

- 至少有一种敌人可以追击、攻击、受伤、死亡，并给玩家奖励。

## 第四阶段：玩家成长

目标：让战斗结果能推动 RPG 成长。

任务：

- 增加玩家等级和经验。
- 金币、货币改成真实存储数据。
- 增加基础背包。
- 根据需要增加装备栏。
- 增加技能解锁或技能升级数据。

交付结果：

- 击败敌人后，玩家能获得奖励，并在当前游戏过程中保留。

## 第五阶段：任务与 UI 整合

目标：用任务目标把战斗和奖励串起来。

任务：

- 决定使用已有的 CustomQuest 插件，还是先写一个更轻量的任务系统。
- 创建一个简单任务，例如击败敌人或收集物品。
- 在 UI 中显示任务状态。
- 任务完成后发放奖励。
- 核心玩法稳定后，再加暂停、设置等 UI。

交付结果：

- 一个能引导玩家完成第一次战斗的简单任务。

## 第六阶段：项目结构整理

目标：让项目后续更容易扩展。

任务：

- 整理脚本目录，例如：
  - `Core`
  - `Gameplay`
  - `Combat`
  - `Player`
  - `Enemy`
  - `UI`
  - `Data`
- 代码量变大后添加 Assembly Definition。
- 定义 Addressables 命名规则。
- 增加简单更新日志或任务列表。
- 后续为场景加载和玩家属性增加基础 Play Mode 测试。

交付结果：

- 项目结构更清晰，后续加内容时不会被旧原型代码干扰。

## 建议执行顺序

1. 修复 Unity Console 编译错误。
2. 确认启动场景和 Addressables 加载流程。
3. 创建并绑定普通攻击 `SkillData`。
4. 测试左键攻击和连击。
5. 增加玩家属性组件。
6. 把 `MainUI` 绑定到玩家属性。
7. 把敌人从“命中即销毁”改成 HP 死亡。
8. 把攻击伤害时机改成动画事件。
9. 做一个完整敌人遭遇。
10. 增加第一个任务或奖励闭环。

## 注意事项

- 同一个输入或玩法行为，只保留一个系统负责。
- 在启动流程和战斗闭环稳定前，不要急着加背包、任务、复杂 AI。
- 优先做小而完整的功能：一个技能、一个敌人、一个 UI 绑定、一个遭遇。
