# RPG-Silent 后续功能开发路线

## 当前定位

本项目目标是做一个可用于面试展示的第三人称 RPG 原型。后续开发优先追求“可演示的完整闭环”，而不是继续堆很多彼此没有连接的新系统。

当前推荐的核心展示链路：

```text
开始界面
-> 进入主场景
-> 玩家移动、跳跃、翻滚
-> 左键普通攻击与连击
-> 敌人追击并攻击玩家
-> 玩家和敌人都拥有真实生命值
-> 击败敌人后获得反馈或奖励
-> UI 显示真实玩家数据
```

## 职责划分

### PlayerController

负责玩家基础输入和基础状态：

- 移动
- 跳跃
- 翻滚
- 姿态切换
- 鼠标左键普通攻击入口
- 玩家受伤和死亡

普通攻击链路：

```text
PlayerController
-> AttackState
-> AttackExecutor
-> EnemyController.TakeDamage
```

### AttackState

负责普通攻击状态和连击逻辑：

- 进入攻击状态
- 维护 `comboIndex`
- 根据连击窗口接收下一次左键
- 设置 Animator 参数 `ComboIndex`
- 触发 Animator 的 `Attack`
- 根据 `AttackProfile` 的时间点调用 `AttackStart`、`AttackRelease`、`AttackEnd`

### AttackExecutor

负责真正执行命中和伤害：

- 根据当前姿态和连击段数读取 `AttackProfile`
- 执行近战扇形、Hitbox、射线、投射物、AOE 等攻击方式
- 统一调用 `ApplyDamage`
- 生成命中特效

### PlayerSkillController

后续只负责技能系统，不负责鼠标左键普通攻击。

建议职责：

- 监听技能键，例如 `Q / E / R / 1 / 2 / 3`
- 管理技能能量
- 管理技能冷却
- 判断技能是否可释放
- 调用技能执行逻辑
- 后续可以对接 `SkillCastManager` 或 `AttackExecutor`

## 第一阶段：基础战斗闭环

目标：让玩家和敌人能完整打一场最小战斗。

### 1. 敌人生命系统

当前优先级最高。

建议给 `EnemyController` 增加：

- `MaxHealth`
- `CurrentHealth`
- `TakeDamage(int damage)`
- `Die()`
- `IsDead`

完成标准：

- 玩家攻击敌人时，敌人扣血。
- 敌人血量归零后死亡。
- 死亡后不再移动、不再攻击。
- 可以延迟销毁敌人对象。

### 2. 敌人受击反馈

建议逐步加入：

- 受击 Debug 日志
- 命中特效
- 受击闪白或材质变化
- 简单击退
- 受击硬直
- 死亡动画或死亡特效

完成标准：

- 玩家能明显感知攻击命中了敌人。
- 敌人死亡不是瞬间无反馈消失。

### 3. 敌人攻击玩家

当前敌人已经有追击和攻击逻辑，后续需要整理成更稳定的状态。

建议状态：

```text
Idle
-> Chase
-> Attack
-> Hurt
-> Dead
```

完成标准：

- 敌人接近玩家后按冷却攻击。
- 玩家被攻击后扣血。
- 敌人死亡后停止攻击。

## 第二阶段：UI 数据接入

目标：主界面显示真实玩家数据，而不是示例值。

### 1. 玩家生命值接入 MainUI

建议让 `PlayerController.TakeDamage` 后刷新 UI，或后续抽出 `PlayerStats` 事件。

短期简单方案：

```text
PlayerController.TakeDamage
-> UIManager 找到 MainUI
-> MainUI.UpdateHP(current / max)
```

中期推荐方案：

```text
PlayerStats.OnHealthChanged
-> MainUI 订阅事件
-> 自动刷新血条
```

完成标准：

- 玩家受伤后 HP 条变化。
- 玩家死亡后 UI 状态能反映出来。

### 2. 能量值接入 MainUI

如果保留 `PlayerSkillController` 的能量系统，后续应显示到 `MainUI` 的 MP 或 Energy 条。

完成标准：

- 能量会自动恢复。
- 释放技能会扣能量。
- UI 能同步变化。

### 3. 奖励数据显示

后续击败敌人后，可以先做最简单的奖励：

- Gold
- Exp

完成标准：

- 敌人死亡后玩家获得金币或经验。
- `MainUI` 上的数值会变化。

## 第三阶段：技能系统

目标：让 `PlayerSkillController` 真正承担技能职责。

### 1. 技能输入

建议先做 2 个技能键：

- `Q`：近战范围技能或冲击波
- `E`：远程投射物或 AOE

完成标准：

- 按技能键能释放技能。
- 技能不会影响左键普通攻击链路。

### 2. 技能冷却和能量

建议每个技能使用 `SkillData` 配置：

- `EnergyCost`
- `CooldownTime`
- `CanBeInterrupted`
- `EffectPrefab`
- `HitEffectPrefab`

完成标准：

- 能量不足时不能释放技能。
- 冷却中不能重复释放技能。
- UI 能显示能量变化。

### 3. 技能执行方式

短期可以直接复用 `AttackExecutor` 的攻击类型：

- Raycast
- Projectile
- InstantAoe
- PersistentAoe

完成标准：

- 技能伤害也能通过统一伤害入口结算。
- 技能命中特效和普通攻击命中特效可以分开配置。

## 第四阶段：任务与奖励闭环

目标：让战斗有目标，而不是单纯测试攻击。

建议先做一个简单任务：

```text
击败 3 个敌人
-> 任务完成
-> 获得金币或经验
-> UI 显示完成反馈
```

完成标准：

- 进入主场景后有一个明确目标。
- 击败敌人会推进目标进度。
- 任务完成后给奖励。

## 第五阶段：展示质量提升

目标：让项目更适合面试演示。

### 1. 开始到主场景流程

确认：

- `StartScene` 能打开开始界面。
- 点击开始能加载 `Main`。
- 加载完成能打开 `MainUI`。

### 2. 战斗演示场景

建议主场景只保留一个小型可控区域：

- 一个玩家出生点
- 2 到 3 个敌人
- 清晰的光照和摄像机
- 简单 UI
- 一个任务目标

### 3. 项目说明文档

建议后续补充：

- 项目简介
- 操作说明
- 系统架构图
- 核心代码说明
- 演示 GIF 或截图
- 已完成功能列表
- 后续优化方向

## 推荐执行顺序

1. 完成 `EnemyController` 的生命值和死亡逻辑。
2. 让 `AttackExecutor.ApplyDamage` 打到敌人时真实扣血。
3. 加入敌人受击反馈和死亡反馈。
4. 让敌人攻击玩家，并让玩家 HP 真实下降。
5. 把玩家 HP 接入 `MainUI`。
6. 击败敌人后给玩家金币或经验。
7. 把奖励数值接入 `MainUI`。
8. 再开始做 `PlayerSkillController` 的 Q/E 技能。
9. 做一个简单任务：击败指定数量敌人。
10. 整理主场景，形成 30 秒可演示版本。

## 面试讲述重点

后续实现时，建议围绕这些点组织代码和说明：

- 输入层和战斗层分离：`PlayerController` 只负责普通输入入口，`AttackState` 负责攻击状态。
- 攻击数据配置化：不同连击段使用不同 `AttackProfile`。
- 命中方式可扩展：近战、射线、投射物、AOE 都走 `AttackExecutor`。
- UI 不写死数据：血量、能量、金币来自真实游戏状态。
- 先做闭环，再做扩展：基础战斗稳定后再加入技能、任务、成长。
