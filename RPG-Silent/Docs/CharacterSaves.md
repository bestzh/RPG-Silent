# 多角色存档

更新：2026-10-28。使用现有职业、男女模型、装备外观、预览控件和字体，不需要下载资源。

后续最终集成回归、第三轮 257 项全量测试、Windows64 构建及独立启动均已通过，详见 [FinalLocalValidation.md](FinalLocalValidation.md)。下文验证条目保留本阶段的原始范围与历史问题。

## 操作

- 开始菜单的“创建角色”打开原有职业与男女选择页。浏览和切换预览不写存档；确认“踏入主城”后先保存新角色，再加载主城。创建失败保留选择页，可以重试，已有角色不会被覆盖。
- “选择角色”显示职业、性别、等级、保存时间及角色编号，每页六个。选择一项可以查看该角色已穿戴防具及当前武器，支持拖动旋转和滚轮缩放；进入主城后继续其成长。
- 原有单角色存档显示为“原有单角色存档”。损坏、版本不兼容或资源不可用的角色仍保留在列表中，不能继续，不会自动进入另一个角色。
- 游戏内通过暂停菜单返回主菜单，再选择其他角色。保存失败时阻止结束 / 切换当前会话，保留玩家和未保存进度供重试。
- 不设固定角色数量，列表分页；此次没有加入角色删除、重命名、跨角色共享仓库或云同步。

## 保存规则

新角色位于 `Application.persistentDataPath/Saves/characters/<角色 GUID>/progress.json`，每个目录有自己的 `progress.backup.json`。原来的 `Saves/progress.json` 及备份保留原位置，通过独立的 `legacy` 入口读取；创建其他角色不会改动旧文件。实际继续旧角色后，沿用既有迁移和保存流程写入当前格式。

没有额外角色索引文件。列表直接读取合法 GUID 目录中的已保存角色，忽略只有临时文件的未完成目录；中断写入一个角色不会影响其他角色的发现。角色数据继续使用 v10，不新增成长字段，也不复制角色之间的数据。旧版 v1–v9 沿用兼容路径。

金币、经验、职业 / 性别、装备实例与强化 / 词条 / 宝石 / 锁定、配装方案、技能等级与技能栏、任务状态、药品数量 / 快捷栏 / 冷却都留在各自完整记录中。目录与数据的角色 ID 不一致时拒绝读取 / 保存。备份仅在本角色目录中恢复；不兼容的未来版本不会被较旧备份覆盖。

主要文件：`ProgressSaveStore.Characters` 负责目录发现与独立读写，`PlayerCharacterProgress` 校验内容和创建初始记录，`PlayerSessionService` 在切换前保存，`StartUI` 与 `CharacterSelectionView` 提供选择入口及只读外观预览。新角色确认采用一次原子主文件写入，不以先创建共享索引或覆盖旧槽位的方式发布。
