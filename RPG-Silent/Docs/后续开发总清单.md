# RPG-Silent 单机版本后续开发总清单

更新日期：2026-10-28  
项目位置：`E:/project/RPG-Silent`  
目标：在现有功能基础上，完善物品管理、角色成长、副本重玩体验和交付质量，形成可持续游玩的单机 RPG。  
文档状态：规划清单；本次仅整理文档，未启动下列新增功能的开发。

## 1. 范围与约束

- 联机、房间、组队同步、服务端校验和云存档继续暂缓。
- 优先使用项目已有的场景、角色、装备、动画、特效、图标、字体和音效。
- 确认资源不足时，先列出资源名称、用途、需要的动画或规格，再由用户决定下载。
- 主城保持禁止攻击；进入副本后按已有规则恢复武器和战斗姿态。
- 开局只有普攻，其他技能仍由对应职业导师教授；新增专精在现有职业与转职体系上扩展。
- 涉及角色外观、装备和预览的内容，继续覆盖男女角色。
- 装备保持手动拾取；金币、经验保持吸附逻辑。
- 丢弃物品放在角色脚边，可以重新拾取；离开场景或退出游戏后消失。
- 保留真实玩家存档。开发与故障验证使用独立测试目录或存档副本。

## 2. 当前基础

以下已有实现，后续工作围绕它们扩展，不应按历史路线文档重复开发：

- 多职业、男女模型、导师学习、技能升级、转职及职业被动。
- 武器装备与切换、拔收动画、主城禁战、连段、技能衔接、锁定、闪避、防御和受击反馈。
- 两张副本地图、Boss 阶段、探索节点、训练场、挑战目标和战斗统计。
- 六档装备品质、手动拾取、独立装备实例、强化、宝石、套装、锻造和重铸。
- 背包外观预览、单件与整套试穿、锁定、批量分解、配装方案和丢弃。
- 主支线与特殊任务、剧情分支、重复委托、NPC 好感记录、成就和图鉴。
- 主城居民与昼夜作息、药品快捷栏、多角色存档及损坏存档恢复。

最新功能记录见 [UnityProjectContext.md](UnityProjectContext.md)。当前存档格式为 v11；后续新增持久数据时需评估版本迁移。最近一次背包丢弃验证为 398 项 EditMode、74 项运行检查通过，详见 [InventoryDiscard.md](InventoryDiscard.md)。这些记录属于已有功能的验证证据，不代表下面所有扩展或最终客户端验收已经完成。

## 4. 详细待办与验收标准

### 01. 背包整理与检索

- [ ] 按品质、等级、类型、获得时间排序；获得时间需要明确旧物品的兼容处理。
- [ ] 支持名称搜索，细分武器、防具、材料、药品和宝石。
- [ ] 显示新获得物品标记及可装备提示。
- [ ] 增加批量出售和批量丢弃，显示本次物品与数量的确认清单。
- [ ] 保留锁定、已穿戴、两武器槽和其他既有操作限制。

**验收标准：** 排序或筛选后仍操作正确实例；批量操作前后数量、金币和地面物品一致；取消、确认失效或写盘失败不会部分扣除。原试穿、配装、强化和分解流程正常。

### 02. 地面掉落操作

- [ ] 增加附近可拾取物品列表，支持选择或切换拾取目标。
- [ ] 处理掉落密集时的名称重叠、遮挡和目标难以选中。
- [ ] 增加品质筛选，明确只影响显示，不删除或自动处理物品。
- [ ] 拾取前查看属性，并与当前对应槽位装备比较。
- [ ] 离开副本前提示未拾取的高品质物品，保持装备手动拾取规则。

**验收标准：** 列表、光标或按键选中的物品与实际拾取一致；距离、遮挡和背包容量检查有效；过滤、重复按键与关闭界面不造成物品丢失或重复领取。

### 03. 主城仓库

- [ ] 复用现有 NPC 或箱子提供仓库入口。
- [ ] 支持装备、材料、药品的存取及数量选择。
- [ ] 支持批量存取、分类、搜索和容量显示。
- [ ] 保留装备实例、强化、词条、宝石和锁定状态。
- [ ] 首期使用角色独立仓库，明确已装备物品与配装引用的处理规则。

**验收标准：** 存取前后背包与仓库总量守恒；满仓、满包、重复点击和保存失败不会复制或吞物品；切换角色、退出并继续游戏后数据隔离且一致。

### 04. 商店与回购

- [ ] 支持批量购买药品和材料，显示数量、总价和容量结果。
- [ ] 增加误出售物品回购，明确价格、容量及记录保留期限。
- [ ] 根据任务进度或 NPC 好感解锁部分商品。
- [ ] 统一购买、出售和回购的失败说明与确认流程。

**验收标准：** 金币与物品变化准确；回购装备保留原实例属性；重复提交和写盘失败不重复扣款或发货；原商店及铁匠补给可正常使用。

### 05. 金色、红色装备特殊效果

- [ ] 配置首批改变玩法的效果，例如精准格挡回能、重击冲击、法术连锁和召唤强化。
- [ ] 为每种效果定义触发条件、持续时间、冷却、叠加上限和适用对象。
- [ ] 在装备详情中显示实际效果，必要时显示触发反馈与剩余冷却。
- [ ] 正确处理换装、武器切换、死亡、切场景和读档时的效果状态。

**验收标准：** 效果进入真实伤害或资源结算；备用武器不会错误提供当前武器效果；不存在无限触发、重复订阅或卸下后继续生效；男女与对应职业均可使用。

### 06. 职业与技能专精

- [ ] 在既有职业被动上设计可选择的普攻、技能、防御或召唤方向。
- [ ] 明确解锁等级、投入资源、互斥关系和成长上限。
- [ ] 在技能升级页展示当前效果与下一级变化。
- [ ] 增加专精重置，明确返还规则和费用。
- [ ] 保留导师学习、职业限制和现有转职进度。

**验收标准：** 专精改变实际战斗行为或数值；重置不会复制投入资源；转职、旧档迁移与技能装备不会出现不可用组合；新角色仍仅有普攻。

### 07. 怪物配合与精英特性

- [ ] 完善近战包围、远程保持距离和支援型怪物配合。
- [ ] 增加护盾、狂暴、治疗等精英特性及清晰标识。
- [ ] 核查卡墙、跨障碍攻击、追击范围和脱战恢复。
- [ ] 统一危险攻击预警、实际命中范围和反击窗口。

**验收标准：** 怪物在现有导航场景中可到达目标；表现与伤害时机一致；受击、死亡、结算和场景卸载能终止行动；精英特性不会意外应用到主城居民或训练奖励。

### 08. 副本随机变化

- [ ] 复用现有地图，组合敌人配置、精英特性和可用探索节点。
- [ ] 增加护送、守点、追击等小型事件。
- [ ] 进入前展示本次额外规则和奖励。
- [ ] 明确随机种子、事件状态与重试规则，保存必要信息。
- [ ] 检查随机组合之间的任务、机关和奖励条件。

**验收标准：** 不出现无法完成的路线、缺失目标或无法到达的宝箱；重试后的行为符合已显示规则；同一事件不会重复结算；现有固定副本流程保持可用。

### 09. 长期挑战内容

- [ ] 增加首领连战、逐层挑战等单机模式。
- [ ] 记录个人最佳时间、最高层数和最佳成绩。
- [ ] 明确首次奖励、重复奖励和领取条件。
- [ ] 设置难度递增、失败退出及重新挑战规则。

**验收标准：** 难度与奖励随规则变化；记录按角色保存；退出、死亡、重试和读档不会刷取首次奖励；挑战不会覆盖普通副本的任务与结算状态。

### 10. 任务与剧情内容扩充

- [ ] 将现有任务串成覆盖不同成长阶段的主线章节。
- [ ] 增加职业专属战斗考验和副本后续故事。
- [ ] 让 NPC 好感进一步影响服务、商品或后续委托。
- [ ] 完善失败、放弃、重新接取和互斥分支说明。
- [ ] 检查新增任务与旧档已完成任务、转职和重复委托的衔接。

**验收标准：** 任务可完整接取、推进、交付；选择影响与界面说明一致；放弃或重接不会绕过互斥条件、重复发奖或造成主线永久卡死。

### 11. 分步骤新手引导

- [ ] 引导移动、普攻、闪避、格挡、学习技能和装备武器。
- [ ] 引导手动拾取、背包整理、强化、仓库和任务交付。
- [ ] 支持跳过、重新查看和退出后继续。
- [ ] 按玩家实际绑定显示按键，按已完成行为推进步骤。

**验收标准：** 新玩家可完成一轮主城到副本再回城的流程；教学不会阻挡正常菜单或战斗；跳过不赠送额外奖励，旧角色不会被强制重新教学。

### 12. 界面与交互统一

- [ ] 逐页测试背包、NPC、仓库、设置、任务与通关界面的真实鼠标操作。
- [ ] 统一确认、取消、返回和关闭逻辑。
- [ ] 检查弹窗叠加、输入阻挡、鼠标锁定及恢复。
- [ ] 覆盖死亡、切场景、加载失败和快速重复开关界面。
- [ ] 适配不同分辨率、窗口比例和长文本。
- [ ] 品质和危险提示同时使用文字、图形与颜色。

**验收标准：** 可见且可用的按钮能收到真实指针事件；关闭全部界面后恢复正确操作；没有文字遮挡关键按钮。不能仅调用按钮回调代替输入验收，参见 [DungeonUIInputFix.md](DungeonUIInputFix.md)。

### 13. 音效、设置与操作舒适度

- [ ] 统一攻击、受击、拾取、任务和菜单交互响度。
- [ ] 根据现有资源完善环境声与战斗音乐过渡。
- [ ] 核查音量、画面、灵敏度、震屏等设置是否实际生效并保存。
- [ ] 检查改键冲突、取消改键、恢复默认和提示同步。
- [ ] 提供适当的震屏、伤害数字及提示强度选项。

**验收标准：** 设置有可观察效果，重启后保持；改键后相关界面与教学同步；菜单不意外触发攻击或镜头移动；声音不会因连续触发无限叠加。

### 14. 成长与经济平衡

- [ ] 实际游玩评估升级速度、技能费用和转职节奏。
- [ ] 检查金币、强化材料、药品和各品质装备掉率。
- [ ] 比较不同职业、武器和专精在同阶段的表现。
- [ ] 验证特殊效果、套装和其他成长组合的强度上限。
- [ ] 检查低难度收益、高难度风险、重复委托和商店之间的经济关系。

**验收标准：** 记录完整游玩的耗时、死亡、消耗和收益；没有明显进度卡死、无限收益或压倒其他选择的单一组合。脚本秒杀、补血或直接发奖的集成测试不能替代手感与平衡验收。

### 15. 存档与长时间稳定性

- [ ] 核查并补齐保存中、成功、失败和重试提示。
- [ ] 为仓库、回购、专精等新增数据设计旧档兼容与迁移。
- [ ] 测试连续切换角色、进出副本、死亡重试和退出重进。
- [ ] 测试文件占用、写入失败、损坏主档和备份恢复。
- [ ] 检查复制装备、重复领奖、丢失物品和跨角色串数据。
- [ ] 进行长时间循环验证，记录失败条件、诊断及恢复结果。

**验收标准：** 每笔交易符合预期的完整提交或完整保留规则；无法读取的原文件不被误覆盖；旧角色完整恢复；测试使用隔离目录，真实玩家存档保持不变。既有恢复问题的修复证据见 [LivingWorldAndProgression.md](LivingWorldAndProgression.md)。

### 16. 性能、完整客户端与交付

- [ ] 测量大量怪物、特效、掉落和主城居民同时存在时的性能。
- [ ] 明确目标机器的帧率、内存和加载时间预算。
- [ ] 检查长期运行后的场景资源、事件订阅、预览模型和渲染纹理释放。
- [ ] 根据实际分析结果优化热点、对象复用和加载流程。
- [ ] 构建包含全部最新代码与 Addressables 内容的 Windows 客户端。
- [ ] 在独立客户端完成创建角色、主城服务、双副本、通关、回城、退出及读档流程。
- [ ] 同步操作说明、资源清单、已完成范围与已知问题，更新过时的历史待办。

**验收标准：** 最新产物与源代码、资源版本对应；记录实际帧率、内存及完整流程结果；仅编辑器通过或独立程序短暂启动不视为完整交付。其他平台与后端构建方式需另列验证范围。
