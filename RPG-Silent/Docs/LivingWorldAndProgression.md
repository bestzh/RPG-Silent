# 任务导航、剧情、委托、锻造、图鉴与主城昼夜

更新：2026-10-28。六项功能已接入当前单机流程，继续复用项目中的 NPC、男女角色、装备、材料、动画、灯光、天空与字体。主城仍禁止攻击，未增加联机或外部资源依赖。当前存档格式为 v11；下方验证仅对应本轮源码和 Unity Editor，没有重新生成 Windows 客户端。

## 如何体验

| 入口 | 当前功能 |
| --- | --- |
| J／HUD「任务」 | 打开冒险手札，切换任务、成就奖励、冒险图鉴；任务支持类别与状态筛选、追踪。 |
| 追踪任务后的右侧 HUD | 显示当前目标、相对镜头方向、直线距离；小地图显示金色目标标记，远目标的标记停留在地图边缘。 |
| 靠近执事阿登、商人罗莎、探险家米拉，按 E | 「交谈 / 故事」阅读多段对话、选择行动、查看影响、确认决定；「任务」页接后续分支及委托。 |
| 靠近铁匠，按 E | 「锻造 / 重铸」中制作装备或重新随机生成词条；原强化、宝石、补给服务继续保留。 |
| 主城活动 | HUD 显示日期与时间，居民按时前往工作点、休息点，守卫保持巡逻。 |

任务目标完成、可以交付、收到奖励和成就达成均有独立提示。提示展示具体奖励；事件写盘失败时保留内存进度并提示重试保存。需要交付的任务仍须返回对应 NPC，不会自动领取奖励。

## 导航规则

- 已达成任务指向对应交付 NPC；职业任务匹配本角色的导师。
- 主城中的副本目标指向现有近距离传送门，标明森林／洞窟，以及限时挑战或首领试炼要求。
- 副本内按当前未完成目标寻找有效敌人、精英事件、宝箱等；精英事件启动后改为追踪实际精英。
- 未发现的隐藏支路只给探索提示，靠近发现后才提供精确位置。前往错误副本时提示返回主城选择正确目的地。
- 当前提供方向与直线距离，不是地面路线或自动寻路。使用 UI 图形绘制地图标记，避免既有字体缺失符号。

## 剧情与任务分支

三段故事各有两页正文和两个互斥决定。确认前显示结果、金币、经验与好感变化，可以取消重新选择；确认后按角色持久保存，允许回顾，不再更改或重复领奖。好感范围为 0–100；一般任务交付增加 5，可重复委托增加 2。

| NPC／故事 | 分支 | 后续任务 |
| --- | --- | --- |
| 执事阿登／主城职责 | 清理威胁／调查遗迹 | 巡防先锋／遗迹先行者 |
| 商人罗莎／市集援助 | 提供材料／护送商路 | 市集援手／商路守望 |
| 探险家米拉／遗迹秘密 | 分享发现／接受挑战 | 失落地图／遗迹试炼者 |

上述六项任务覆盖森林精英、宝箱、两地隐藏支路、材料交付、森林击杀与洞窟首领试炼。每个角色只能开启各故事选定的一条路线；另一条显示未满足剧情条件。当前任务资产共 28 项，按职业过滤后每角色显示 24 项（包含尚未解锁、互斥和已完成项）。原 19 项任务的资产、目标顺序和持久 ID 保留。

对话资源在 `Assets/Resources/Adventure/Story-*.asset`；任务分支条件配置在 `QuestDefinition.RequiredStoryId / RequiredChoiceId`。选择、即时奖励、好感与后续解锁使用同一次存档事务。

## 装备锻造与词条重铸

新增 13 张配方，成品全部使用已有装备配置和外观：

| 解锁条件（提交对应任务） | 配方 | 单次消耗 |
| --- | --- | --- |
| 铁匠的备料 | 蓝色单手剑、重剑、弓、法杖，共 4 张 | 金币 240、锻造碎片 ×8、晶核碎片 ×2 |
| 晶核研究 | 现有水晶系列头部、胸部、脚部、戒指、项链，共 5 张 | 金币 240、锻造碎片 ×8、晶核碎片 ×2 |
| 城外的最后威胁 | 紫色单手剑、重剑、弓、法杖，共 4 张 | 金币 650、锻造碎片 ×16、晶核碎片 ×6 |

旧档已完成这些任务时直接识别解锁。锻造成品具有独立装备 ID 和按品质生成的随机词条；背包满时进入原有待领取。背包及待领取都满时拒绝制作，不扣资源。

绿、蓝、紫、金、红品质装备可以重铸；白色装备没有随机词条。重铸需确认消耗，重新随机全部词条，结果可能提升或降低。装备 ID、品质、强化等级、宝石、穿戴状态和男女外观保留，已穿戴装备的属性即时刷新。锁定装备不可重铸；确认前装备状态发生变化时要求重新确认。

重铸费用按现有品质枚举值 `tier` 计算：金币 `100 + 75 × tier`、锻造碎片 `2 + 2 × tier`、晶核碎片 ×1。当前 `tier` 为白 0、绿 1、蓝 2、紫 3、金 4、红 5。锻造／重铸都要求玩家在主城铁匠附近、存活且处于可管理装备的状态；保存成功才扣费和应用结果。

## 成就与图鉴

首批 10 项成就包括首次击杀、累计普通敌人击杀、首领首杀、两种首领收录、六种装备收集、两处秘密、首次通关、精英猎手、首次锻造和三次委托。达成后在 J 手札的「成就奖励」页手动领取，每角色每项只能领取一次。领取失败不扣除领取资格、不重复发放。

「冒险图鉴」分普通怪物、Boss、装备、隐藏区域四类。未发现项隐藏具体资料；击败或发现后显示已有资源的名称、资料和次数。初始敌人目录包含四种普通怪、两种 Boss；两处隐藏区域采用稳定 ID `forest-hidden`、`cavern-hidden`。装备按物品类型收录，出售／分解后记录仍保留。

已有存档会补录当前持有的装备；过去未记录的击杀、秘密发现和通关不会凭空补算。怪物记录接入副本服务已登记、已去重的死亡事件，训练假人和御兽师召唤物不计入敌人图鉴。物品记录随同获得装备的事务保存。

## 主城昼夜与作息

- 一个游戏日为主城内经过的 20 分钟；每角色初始为第 1 天 08:00，保存各自日期与时间。时间只在主城加载期间前进，不模拟离线经过时间。
- 09:00–17:00：8 位普通居民前往各自工作点；20:00–06:00：前往住宅附近的休息点；其他时段沿既有路径活动。2 位守卫全天保留巡逻。
- 3 位委托 NPC 和原 4 位服务 NPC 夜间仍可交互，任务、导师与铁匠不会因为夜晚失去入口。
- 复用现有行走、站立动画；“休息”表现为返回休息位置停留，没有新增卧床动画或房屋室内场景。
- 现有方向光的角度、强度、色彩与环境光随时间变化；对项目现有程序天空材质创建运行时副本调节夜晚亮度，不修改原天空资产。卸载主城会恢复并释放，训练场和两座副本不携带主城灯光控制器。
- 每 30 秒自动保存时间，并随其他进度保存；保存失败保留原有提示和重试入口。

## 存档恢复偶发失败：证据与修复

此前 `CorruptPrimaryRecoversPreviousCompleteTransaction` 偶发在“备份恢复成功后再保存”失败。本轮为保存失败增加异常类型、HResult、堆栈诊断；先复现，再单独比较替换方式。

| 检查 | 结果 |
| --- | --- |
| 原流程：连续损坏主档、从备份加载、保存、再读 | 300 次中失败 10 次 |
| 独立 A/B：`File.Replace` 不传备份目标 | 300 次中失败 1 次 |
| 独立 A/B：保留被替换文件 | 300 次，0 失败 |
| 最终修复：完整恢复链路压力检查 | 500 次，0 失败；每次检查有效备份与被替换文件 |

捕获到 Windows `IOException 0x80070497`，即 `ERROR_UNABLE_TO_REMOVE_REPLACED (1175)`，堆栈指向 `File.Replace(temporary, destination, null)`。这是已证实的失败路径，不据此断言操作系统删除失败由杀毒、并发进程或某个硬盘问题引起。Windows 对该错误的约定见 [Microsoft ReplaceFile 文档](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew)。

修复：正常有效主档仍轮换至 `progress.backup.json`；恢复损坏主档时，原损坏内容移至固定的 `progress.json.replaced`，让替换操作有明确的保留目标，且不覆盖有效恢复备份。该文件名固定，不会每次恢复无限新增文件。临时文件仍先完整写入并 flush，再原子替换；没有降级成“先删除原档再写入”。

另外，若主档因权限或占用无法读取，普通保存会拒绝覆盖，而不是把“不可读”当成损坏后强行写入。新增 50 次循环恢复回归和被占用主档保护测试。诊断位于 `ProgressSaveStore.LastFailureDiagnostic`，用户界面继续显示清晰的保存失败信息。
